# WerareMods Bot

## Установка

1. Установи Python 3.10+
2. Установи зависимости:
   ```
   pip install -r requirements.txt
   ```
3. Открой `config.py` и вставь свой токен бота (получить у @BotFather):
   ```python
   BOT_TOKEN = "твой_токен"
   ```
4. Положи в эту же папку файл `photo.jpg` — именно эта картинка будет
   прикрепляться абсолютно ко всем сообщениям бота (как ты и просил).
5. Запусти бота:
   ```
   python bot.py
   ```

База данных `bot.db` создастся автоматически при первом запуске.

## Что умеет бот

- **/start** — приветствие с фото и кнопками «🗝Наш канал» / «👤Профиль».
- **Профиль** — показывает ID, имя, username и количество скачанных файлов.
- **/post** (только админ) — присылаешь текст, бот показывает превью с
  кнопками «Отмена» / «Отправить», после подтверждения рассылает текст
  (с фото) всем пользователям из базы.
- **/admintool** (только админ):
  - **📌 Обяз. подписка** — показывает список каналов, кнопки
    «➕ Добавить канал» / «➖ Убрать канал» (просто присылаешь ссылку
    на канал следующим сообщением).
  - **📁 Добавить файл** — присылаешь файл, бот сохраняет его и выдаёт
    диплинк вида `https://t.me/ИМЯ_БОТА?start=file_1`. Если у бота
    настроена обязательная подписка — пользователь по этой ссылке
    сначала должен подписаться на все каналы, иначе файл выдаётся сразу.

## ⚠️ Локальный Bot API сервер (лимит файлов до ~2 ГБ)

Стандартный облачный Bot API ограничивает приём файлов 20 МБ. Так как
у тебя есть VPS — поднимаем свой сервер `telegram-bot-api`, тогда лимит
вырастает до **~2 ГБ** (это максимум, который вообще поддерживает Bot
API, 5 ГБ Telegram не даёт даже через локальный сервер).

### Шаг 1. Получи api_id и api_hash

Зайди на https://my.telegram.org/apps, залогинься своим номером,
создай приложение — получишь `api_id` (число) и `api_hash` (строка).
Они нужны серверу, не самому боту.

### Шаг 2. Собери и запусти telegram-bot-api на VPS

```bash
sudo apt update
sudo apt install -y make git zlib1g-dev libssl-dev gperf cmake g++

git clone --recursive https://github.com/tdlib/telegram-bot-api.git
cd telegram-bot-api
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
cmake --build . --target install -j $(nproc)
```

Запуск сервера (замени `API_ID` и `API_HASH` на свои):

```bash
telegram-bot-api --api-id=API_ID --api-hash=API_HASH --local --http-port=8081
```

`--local` включает режим, в котором сервер отдаёт боту прямой путь к
файлу на диске вместо скачивания по HTTPS — полезно, если захочешь
потом читать файлы напрямую.

Чтобы сервер работал постоянно, оформи его как systemd-сервис
(пример `/etc/systemd/system/telegram-bot-api.service`):

```ini
[Unit]
Description=Telegram Bot API server
After=network.target

[Service]
ExecStart=/usr/local/bin/telegram-bot-api --api-id=API_ID --api-hash=API_HASH --local --http-port=8081
Restart=always
User=root

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-bot-api
```

### Шаг 3. Настрой бота на использование локального сервера

В `config.py` уже добавлена строка `LOCAL_API_URL` — оставь как есть,
если сервер и бот на одной машине (`http://127.0.0.1:8081`). Если
сервер на другой машине/порту — поменяй адрес.

Всё, `bot.py` уже настроен подключаться через этот сервер — просто
запусти его как обычно (`python bot.py`).

### Проверка

Отправь боту через `/admintool → 📁 Добавить файл` файл больше 20 МБ
(например 100–500 МБ) — если всё настроено верно, он примет его без
ошибки "file too large".

Если понадобится реально гонять файлы по 1.5–2 ГБ — учти, что VPS
должно хватать диска и трафика на такие пересылки, а сама отправка
пользователю может занимать заметное время.

## Важные нюансы

- Чтобы проверка обязательной подписки работала, **бот должен быть
  добавлен администратором** в каждый канал из списка обязательной
  подписки — иначе Telegram не даст боту узнать, подписан ли
  пользователь.
- ADMIN_ID уже прописан в `config.py` (8171375787) — команды
  `/post` и `/admintool` доступны только этому ID.
